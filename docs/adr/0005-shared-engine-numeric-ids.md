# All Namespaces share one Storage Engine and one WAL, keyed by numeric IDs

Every Namespace on a Node lives in the same Storage Engine and the same WAL, separated by a key prefix of numeric IDs (`namespace_id ‖ collection_id ‖ …`); the Catalog maps names to IDs. One WAL means one fsync stream and lets a transaction span Namespaces without two-phase commit; numeric IDs make renames a Catalog update and drops a range delete. Tenant isolation is therefore logical (enforced by Roles), not physical: a Transaction may span Namespaces, and the User needs a suitable Role on every Namespace it touches. Per-Namespace engines would have given easier per-tenant backup and deletion, at the cost of many WALs and distributed commit even on one Node.
