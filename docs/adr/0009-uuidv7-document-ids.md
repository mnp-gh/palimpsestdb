# Generated Document IDs are UUIDv7

When a Document is inserted without `_id`, PalimpsestDB generates a UUIDv7 (RFC 9562) stored as BSON Binary subtype 4. This deliberately departs from MongoDB, which generates ObjectIds. Clients may still supply ObjectId `_id`s, so data imported from MongoDB keeps its IDs and the references to them.

## Considered Options

- **Generate ObjectId**: 12 bytes, the smallest, and native to MongoDB tooling. Rejected because IDs from one process differ only by an incrementing counter, so they are guessable, and its timestamp has only second precision and runs out in 2106.
- **Generate UUIDv7 as Binary subtype 4** (chosen): 16 bytes, 74 random bits per ID so IDs cannot be guessed, millisecond time order, and a standard type BSON and other systems already recognise.
- **Generate ULID as a string**: easiest to type in the shell, but about 1.5× the space of the chosen option, not a standard, and indistinguishable from strings users choose.
- **Also reject client-supplied ObjectId `_id`s**: briefly implemented, then reverted. It made every MongoDB import fail (ObjectId is MongoDB's default `_id`) for no technical gain; guessability only matters for IDs we generate.

## Consequences

- IDs generated by one process sort in creation order, so inserts append at the end of a Collection's keyspace.
- Clients write UUIDs in Extended JSON as `{"$uuid": "..."}`; the shell prints them the same way.
